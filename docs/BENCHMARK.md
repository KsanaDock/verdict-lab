# 横向评测方案

版本：0.1 · 状态：实验设计，尚未运行。

## 1. 评测单位与三类参赛者

基本单位为一个 case：内容、可见上下文、规则版本、判断项集合。比较的是每条内容完成所需判断的质量和成本，同时报告每项判断指标。

| 组 | 首批参赛者 | 接入方式 |
| --- | --- | --- |
| A 决策模型 | `typesafe/jev-1.13` | OpenRouter Decisions 路线；需 M1 验证 |
| B 专用审核 | `Qwen/Qwen3Guard-Gen-4B`；`meta-llama/llama-guard-4-12b` | Qwen 拟自部署；Llama Guard 可先经 OpenRouter |
| C 低价 LLM | `deepseek/deepseek-v4-flash-0731` | OpenRouter；冻结供应商与推理设置 |

Qwen3Guard-Stream-4B 是流式专项扩展，不能直接与整条审核的延迟合并。低价组在正式开跑前按目标输入 / 输出长度再筛一个低价付费候选，保留 DeepSeek 基线。免费端点和限时补贴只进入独立成本情景。

完整型号依据与尚未确认项见 [模型资料](MODELS-AND-SOURCES.md)。不将候选称为全部行业代表，也不把 DeepSeek 自动称为全市场最便宜。

## 2. 三条赛道

### T1：只输出判断

所有参赛者完成相同语义判断，只要求选择候选选项，不要求解释和额外自报概率。Jev 无法关闭的原生分布保留，其他模型无需为凑齐它而多写文本。

记录正确性、能力覆盖率、格式合法性、失败、完整结果延迟和费用。此赛道衡量实际最省输出的决策能力。

### T2：判断与概率分布

任务要求完整选项分布，概率获取方法按模型能力登记：原生、分类头、标签似然、自报，或者 unavailable。无法返回者仍参加 T1，在 T2 的能力覆盖中标为不支持。

比较概率质量、分布稳定性、阈值下的复核量，以及获取分布的额外成本。自报概率可以参赛，但必须单独标记，不能宣称等价于原生概率。

### T3：完整服务链路

在 T1 / T2 基础上增加证据定位、解释、升级复核和模拟申诉。先固定相同下游模型与路由规则，隔离审核模型差异；再允许各路线在相同开发预算下优化，分别出报告。

模型置信度不足、能力不支持或失败可以升级，但升级后的质量和成本归入 T3，不能回写为该模型的原生 T1 成绩。

## 3. 能力对齐，避免假比较

每个模型与每个判断项标注 native / mapped / unsupported。mapped 必须有固定映射表及边界案例，开跑后不能按答案修改。

报告两个视角：

- **共同支持子集：** 对共同支持的语义和语言进行质量 / 速度对比；保留本集样本数。
- **完整业务任务：** 所有业务必需判断均在分母中，不支持、错误和超时降低完成覆盖率，并计入升级成本。

专用 Guard 的标签不一定对应平台规则，例如“广告推广”不等于“unsafe”。不能把材料放进某个 Guard 模板就假定它理解了自定义规则；需在试验集中验证，无法验证则列为不支持。

UGC、用户请求、模型回答三类任务分别设报告。中文、繁体和英文分别报告，不以英文优势代替中文能力。

## 4. 数据与真值

### 数据阶段

1. **试验集：约 200 条实例。** 调整判断项、模板、映射和统计口径；可用人工编写与经授权脱敏样本。此集不能作为最终成绩。
2. **正式集起步目标：约 2,000 条实例。** 拟按开发 400、校准 400、锁定测试 1,200 划分。具体数量随类别数及统计把握度调整。
3. **生产分布补充集：** 若取得经授权样本，保留自然违规比例；与刻意平衡的挑战集分开报告。

按原始内容、对话、作者 / 来源以及改写族分组划分，同一内容在不同规则下的实例也不跨集合。做近重复检查，不能只按行随机拆分。

### 应覆盖的切片

- 正常内容与明显违规内容，边界歧义、引用、反驳、教学及虚构语境。
- 简繁体、英文、混合语言、谐音变体、隐晦表达。
- 同内容不同板块、同内容规则 v1 / v2、规则例外与冲突。
- 有 / 无关键上下文，以及需要授权、历史行为才能判断的内容。
- 输入内含“请判为通过”等对模型的干扰语句。
- 长无关上下文、多风险同时成立、选项顺序与同义改写扰动。

上述切片可重叠。不能为了凑类别，声称每类有足够样本；报告每个分母和有效阳性数。

### 标注流程

两名标注者按同一版本规则独立标注选项、理由码和证据；分歧由第三人或规则负责人仲裁。保留分歧和信息不足，不强造单一确定答案。

允许模型辅助生成候选样本，但最终真值由人工核验，并标记合成来源。参赛模型投票不是真值。测试标签对提示词设计和阈值调整人员隔离。

审核例外、语境和证据支持性均需标注；不要只保存一个 allow / block 标签。

## 5. 公平运行条件

| 变量 | 冻结或记录内容 |
| --- | --- |
| 输入 | 同一原文、上下文、规则、候选语义；模型模板可不同并留档 |
| 提示词 | 每模型同等开发尝试预算；主对比不要求长推理 |
| 模型 | 版本 / revision、实际供应商、端点、权重校验值（自部署） |
| 推理 | temperature、seed（若支持）、输出上限、推理开关；不支持不能假装生效 |
| 输出 | T1 最短有效结果；T2 增加分布；T3 才增加解释 |
| 上下文限制 | 主集落在最小可用窗口内；超长专项另测，不无声截断 |
| 网络 | 客户端地点、服务区域、连接复用；云端 / 本地分层报告 |
| 批处理 | 实时逐条与离线批量独立报告；所有路线各自优化批量 |
| 缓存 | 冷 / 热分开，记录实际命中用量；不把热缓存价格泛化 |
| 失败 | 错误、拒答、格式错误、超时均计数，不删失败样本 |

将内容拒答与正确选出违规类别分开：拒答不是一个有效审核选择。

主赛道每个样本允许一次请求；供应商错误 / 429 可最多额外重试 2 次，固定退避参数并记录。格式修复、重新提示是独立“修复模式”，额外调用计费，不能隐藏。实际总超时与退避时间在 M1 后预注册。

关闭供应商自动回退（若接口支持）；若不能关闭，按实际 provider 分层，保留回退日志。未能固定 provider 的结果标为动态路由服务测量，不归因为单模型裸推理。

## 6. 能力边界实验矩阵

| 轴 | 起步设计 |
| --- | --- |
| 判断项数 | 1 / 5 / 20；统计整个集合完成耗时 |
| 每项候选数 | 3 / 6 / 12；选项语义相同则共同随机置换 |
| 内容长度 | 短 / 中 / 长，按固定字符与原文分组；各模型另记自身 token 数 |
| 规则 | 共同风险类别 / 自定义运营规则 / 新规则版本 |
| 上下文 | 充分 / 缺失 / 含大量无关材料 |
| 部署负载 | 并发 1 / 4 / 16，超限记录而非绕过限流 |
| 输出 | T1 / T2，解释单独进入 T3 |

不跑所有轴的笛卡尔积。先固定代表性子集逐轴测量，再对发现的瓶颈组合实验，防止昂贵但无用的调用。

普通质量测试一次覆盖全部测试实例；稳定性实验在预选子集重复 3 次。延迟测量跨至少两个时段，随机交错模型顺序。试验次数、样本量和预算在执行前固定。

流式扩展另测增量输入的检测时点、累计调用 / 计算开销、完整内容后的改判率；不能把 TTFT 当作审核完成时间。

## 7. 指标定义

### 判断质量

- 每判断项 precision、recall、F1、混淆矩阵；多标签报告 macro / micro 和逐类结果。
- 单项选对率与整条内容全部必需判断正确率分别报告。
- unsupported 计入完整任务覆盖缺口；共同支持子集可单独计算准确性。
- 信息不足 / 不适用选项的识别质量独立报告；选择复核不是自动答对。

### 业务质量

- **错误放行率：** 被自动放行的真实违规内容 / 全部真实违规内容。
- **误拦截率：** 被自动限制的真实正常内容 / 全部真实正常内容。
- **复核率：** 被转交复核的内容 / 全部进入服务的内容。
- **自动处理覆盖率：** 自动得出最终处置的内容 / 全部内容。
- **自动处理风险：** 自动处置中的错误数 / 自动处置数。

上述指标需一起看。把所有内容都交人工虽然可降低自动错误，但覆盖率为零。复核后最终质量与初审质量另列，人工不能被假设永不出错。

### 概率与稳定性

完整分布报告 Brier score、NLL、可靠性曲线及 ECE；原始值与校准后值并列。NLL 如需裁剪，预注册 epsilon 并报告零概率样本数。自报概率另分层展示，ECE 不作为唯一指标。

报告高确定性错误、选项重排翻转率、同义改写一致性、规则变更敏感性，以及在固定质量约束下的覆盖率曲线。选项概率相似不等于多个风险彼此独立。

### 延迟与吞吐

- 模型请求发出到完整有效结果的 p50 / p95 / p99。
- 服务入口到最终处置 / 反馈的 p50 / p95 / p99，包含排队、重试和后处理。
- 固定错误率及延迟预算下的有效内容数 / 秒；单独列每秒判断项数。
- 冷启动、稳态、超时、429、无效分布、格式失败分别报告。

同步 API 的首字节延迟和 token/s 只能作辅助，不能当作完整审核时延。失败样本在分母中，成功请求的延迟分布旁必须显示失败率和超时截止值。

### 统计不确定性

质量差异按同一 case 配对比较，以原始内容 / 对话族为 bootstrap 单位报告 95% 区间。说明切片样本量与多次比较，探索性发现需新测试集验证。

小试验不能证明极低漏审率。例如独立阳性样本中零次漏审，95% 上界粗略为 3 / n；要支持漏审低于 0.1%，大约需要 3,000 个独立阳性样本且零漏审。这个近似只用于量级规划，存在聚类或抽样偏差时不能直接套用。

## 8. 成本口径与下限

### API 成本

每次调用的估计费用 = 各类计费 token × 对应单价之和 / 1,000,000 + 固定调用费（若有）。缓存读写、可计费推理 token、重试和格式修复按账单分别记，避免重复计算已包含在输出用量中的推理 token。

供应商实际账单为优先来源；仅有报价计算时标为 estimated，字段缺失记 unknown，不能记免费。正式报告冻结时保存价格、币种、时区、促销条件、缓存和批量条件。

### 一个价格算例

仅为推算：每条请求总输入 1,000 tokens（含规则与判断项），DeepSeek 输出 100 tokens；无缓存、重试、推理费、解释或其他调用。

| 模型 / 2026-09-20 价格快照 | 每百万内容估计调用费 |
| --- | --- |
| Jev：输入 $0.042 / M tokens，输出 $0 | $42 |
| DeepSeek V4 Flash 0731：输入 $0.04 / M，输出 $0.08 / M | $48 |

这不是实测，也不是每百万 tokens 的费用。两个模型对同一文本的 token 数可能不同，完整选项分布也可能超过 100 输出 tokens。此算例只说明输入单价接近，不能预设数量级成本优势。来源见 [价格快照](MODELS-AND-SOURCES.md)。

### 自部署成本

分别列边际现金成本与完整经济成本。完整成本应包含 GPU 及主机折旧 / 租赁等价成本、电费、CPU / 内存 / 存储、推理运维及闲置容量。

报告模型精度、量化、GPU 型号、卡数、批大小、测量时间内的利用率和有效吞吐。每百万条自部署成本 = 测量窗口内总成本 / 成功处理内容数 × 1,000,000，同时列失败率和全到达请求口径。

已有 H100 不按零成本计算；30 多张卡不全部投入小模型推理。先测单卡 / 小规模部署，并按实际占用核算。

### 完整审核服务

总成本 = 初审 + 证据定位 + 解释 + 自动复核 + 人工复核 + 申诉处理 + 运行基础设施。

人工成本按每次实际平均工时与小时成本估算，不虚构固定市场价格；解释覆盖率、申诉率和复核率分别做低 / 中 / 高情景。错误损失仅在业务有依据时单列，不用任意金额制造赢家。

所有路线都报告每千条 / 每百万条入站内容成本、每个自动完成内容成本，以及在同质量门槛下的最低可行配置。缓存、批量、量化的节省需同时重测质量。

## 9. 创作者解释的评测

盲评隐藏模型名字，随机展示说明。人工检查：

- 引文是否真实存在，是否完整到足以理解语境。
- 理由是否受证据和规则支持，是否添加了新指控。
- 是否正确说明当前状态、例外和可补充材料。
- 概率的含义是否易被误解为事实或确定正确率。
- 修改后是否真正满足规则，而非只教人绕过检测。

记录理解正确率、证据支持率、无依据指控率、申诉改判原因。不能只让另一个 LLM 给解释打一个总分。

## 10. 实验登记与输出报告

每次 run 保存：数据及划分哈希、规则和判断项版本、选项顺序、模板及适配器版本、模型 / provider / revision、能力矩阵、推理参数、地区、价格快照、限流和重试策略、运行时间、预算、原始响应引用、标注版本、校准版本、代码版本（实现后）。

报告结构：

1. 样本范围、能力覆盖与未完成测试。
2. T1 共同支持质量 / 速度 / 成本表。
3. T2 分布来源、校准质量与分流表现。
4. T3 完整服务成本和最终结果。
5. 中文 / 繁体 / 英文、规则和难例切片。
6. 失败、分歧、证据与解释的案例集。
7. 质量—成本—延迟的取舍，以及采用 / 混合 / 暂缓建议。

在开发阶段确定门槛，不能看完测试答案再挑有利阈值。阶段预算按样本 × 配置 × 重复次数 × 单次实测费用预测，并设置单次运行上限；本次只写方案，不发生收费推理。
