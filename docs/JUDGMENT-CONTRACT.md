# 判断项与结果契约

版本：0.2 · 状态：核心方向分数与运行记录已实现，完整服务契约待实现。

## 1. 输入以判断为单位

一个测试实例由“内容 + 上下文 + 规则版本 + 判断项集合”构成。同一内容配不同规则可得到不同合理结论。

| 字段 | 含义 |
| --- | --- |
| case_id / content_id | 实例标识 / 内容标识；内容可对应多个规则实例 |
| content_revision / content_hash | 内容版本及完整性标识 |
| content | 待审核原文；首期文本 |
| context | 对话、板块、必要行为记录；标注来源与缺失项 |
| language | 语言及必要的地区表达标签 |
| policy_id / policy_version | 规则包及不可变版本 |
| policy_text | 规则、例外和适用条件 |
| judgments | 需要回答的判断项列表 |
| task_mode | UGC 内容审核 / 用户请求审核 / 模型回答审核；不可混用 |

内容与上下文按不可信材料传入，不得让其中的“忽略规则”等文字改变任务。适配层只做固定序列化和协议转换，不增加隐藏语义提示。

## 2. 判断项的最小组成

| 字段 | 设计要求 |
| --- | --- |
| judgment_id / version | 稳定标识；定义变更就升版本 |
| question | 一项清晰判断，避免混入几个不同概念 |
| selection_mode | single_choice 或 multi_label |
| options | 选项 ID、名称、具体适用条件、排除条件 |
| policy_refs | 关联规则条款，不以选项名字代替条款 |
| applicability | 哪些输入适用；不适用与未发现风险不同 |
| examples | 简短正反例，属于所有模型相同的可见输入 |
| depends_on | 条件判断依赖；前置缺失时不能假装已知 |
| evidence_requirement | 所需上下文或证据片段；缺失如何处理 |

候选选项的粒度应帮助下一步服务。对于站外引流，可区分普通资料引用、交易信息、引导站外联系、无相关内容、信息不足。

### 单选、多标签与程度

- **单选：** 同一判断维度的选项尽量互斥且覆盖可见情况；必要时有其他、信息不足、不适用。
- **多标签：** 多个独立风险可同时成立。实现时可拆为逐类别单选判断，每类使用出现 / 未出现 / 信息不足；不强迫风险类别之间互斥。
- **程度：** 如无、轻度、明显、严重。保留等级分布与被选等级；期望分数仅作辅助，不把整数分数误当连续真实风险。
- **复合理由：** “商业目的 + 站外联系方式”来自两个判断，由策略规则组合。不能把两个概率相乘当成联合概率，除非有经过验证的模型假设；首期不用这种假设。

信息不足是语义选项；API 失败、模型不支持是系统状态，不能伪装成这个选项。

## 3. 首批判断维度草案

这些是产品设计草案，需经试验集人工审阅后冻结，不声称现成审核模型全部支持。

| 判断维度 | 示例选项 | 为什么有用 |
| --- | --- | --- |
| 内容用途 | 日常讨论 / 信息引用 / 商品交易 / 服务推广 / 其他 / 信息不足 | 区分普通内容与商业目的 |
| 站外联系引导 | 无 / 普通引用链接 / 邀请站外联系 / 信息不足 | 识别需要进一步套用板块规则的内容 |
| 定向攻击 | 无 / 批评观点或作品 / 针对个人攻击 / 信息不足 | 避免把批评直接当辱骂 |
| 威胁表达 | 无 / 引用或虚构语境 / 针对对象的威胁 / 信息不足 | 结合语境识别风险 |
| 个人信息暴露 | 无 / 可能包含敏感个人信息 / 信息不足 | 仅判可见内容，授权状态另问 |
| 引用语境 | 无明显引用 / 报道或批判性引用 / 认同或鼓励性引用 / 信息不足 | 判断规则例外是否适用 |
| 规则例外 | 适用 / 不适用 / 信息不足 / 此项无例外 | 使例外判断可审计 |
| 证据充分性 | 足够 / 缺对话上下文 / 缺授权材料 / 缺行为记录 / 其他不足 | 指导复核 Agent 取证 |

对真实用户身份、授权真伪、内容真假等输入无法证明的事项，不让模型自行补全事实。

## 4. 标准化输出

| 字段 | 含义 |
| --- | --- |
| run_id / case_id / policy_version | 绑定实验、输入和规则版本 |
| model_id / revision / provider | 请求模型、实际版本、实际供应商 |
| adapter_version / config_hash | 适配器和完整推理设置 |
| judgment_id | 对应哪项判断 |
| status | ok / unsupported / invalid_output / timeout / provider_error / skipped_dependency |
| selected_option_ids | 原生或经声明映射的选择；失败时为空 |
| selection_source | native / fixed_mapping / derived_from_scores |
| option_probabilities | 每个选项的估计；不可用为 null |
| probability_source | native_distribution / classifier_scores / label_likelihood / self_reported / unavailable |
| native_confidence | 供应商独立置信字段及其说明；不可用为 null |
| calibration_id | 本项目的校准版本；未校准为 null |
| calibrated_probabilities | 独立保存的校准结果，不覆盖原始值 |
| evidence_refs | 原文片段标识、起止位置、引文与校验状态；缺失为空 |
| reason_codes | 已定义的理由码，关联选项和规则；不作为模型思考轨迹 |
| raw_response_ref | 原始响应的可追溯位置 |
| timing / usage / cost | 完整响应耗时、token、费用来源与测量口径 |

规则引擎额外产生 disposition（allow / hold / restrict_suggested）、routing_reason、strategy_version。它们与模型的 selected_option_ids 分开保存。

UGC 的“允许发布”和 Guard 的“safe”不必相同：例如某社区禁止广告，但广告未必属于模型的有害内容类别。映射表必须逐项写明语义差别。

## 5. 概率的统一规则

1. 单选分布只在该判断的完整候选集合内归一化。记录候选集合版本；换选项可能改变分布。
2. 多标签各维度的概率独立展示，不要求跨风险总和为 1。
3. 缺少选项概率不能以 one-hot（选中项 1、其余 0）补齐。只有部分 top-k 时标注不完整，不冒充完整分布。
4. 模型自报“0.9”、标签 logprob、分类头 softmax 和原生分布分别记来源；都不自动视为校准概率。
5. 多 token 标签的似然取法、截断、归一化必须记录；单个首 token 概率不是整个判断正确率。M1 无可靠取法时先记 unavailable。
6. Jev 的 confidence 是分布摘要，不当作“该结论正确的概率”，也不与其他模型的同名字段直接比较。见 [官方说明](https://docs.typesafe.ai/confidence)。
7. 在独立校准集拟合，在冻结测试集评估。测试集标签不参与校准或阈值选择。
8. 选项和概率不一致时标记 consistency_error；保留原始记录，主赛道不偷偷改正。

完整单选分布应有唯一选项键、有限的 [0,1] 数值且和接近 1。拟议容差为 1e-3，开跑前冻结。超差标记 invalid_distribution，不能无声归一化后当成正常原生结果。

## 6. 示例：同一内容在不同板块的结果

以下文本、规则、概率和状态均为设计示例，不来自任何模型实测。

**内容 C-001：** “我整理了一套摄影教程，感兴趣可以加我站外账号领取。”

**规则 P-A / v1：** 摄影讨论区允许资料分享，但禁止通过站外联系方式引流；引用公开参考资料不属于引流。

**规则 P-B / v1：** 教程交易区允许站外联系，但须标记商业推广；缺标记时先要求补充。

用完全相同的内容分别构成 C-001-A 与 C-001-B。两个实例应属于同一数据划分组，避免泄漏。

| 判断项 | 示例分布 | 被选项 |
| --- | --- | --- |
| 内容用途 | 讨论 0.04；引用 0.08；交易 0.10；推广 0.70；其他 0.03；不足 0.05 | 推广 |
| 站外联系引导 | 无 0.01；引用链接 0.03；邀请站外联系 0.94；不足 0.02 | 邀请站外联系 |
| 定向攻击 | 无 0.97；批评观点 0.01；个人攻击 0.01；不足 0.01 | 无 |

这些分布是不同判断维度，不能相加。此例没有展示任何联合分布或校准正确率。

**证据片段：** “感兴趣可以加我站外账号领取”。由原文匹配验证存在，证据是否足以支持理由另行评测。

**策略示例：** P-A 中进入限制建议 / 复核；P-B 中检查商业推广标记并要求补充。相同语义判断因平台规则不同，产生不同服务动作。

**创作者说明示例：** “这段内容包含‘加我站外账号领取’，当前讨论区规则禁止站外引流，因此内容进入复核。若这段文字属于引用或有其他上下文，可以补充说明。”

该说明仅基于可见原文与 P-A；不得添加“多次违规”“涉嫌诈骗”等未被证据支持的结论。

## 7. Agent 消费与留痕

- 每个下游环节接收不可变审核记录 ID、输入版本、规则版本及明确的能力缺失信息。
- 证据、解释、复核分别记录 model / prompt / strategy 版本与费用；禁止把额外调用并入 Jev 的原生能力。
- 缺证据或模型分歧产生升级记录；失败不能默认放行或默认认定违规。
- 申诉包含新的材料和原结论；复核输出 supersedes 关系形成新记录，旧结论仍可追溯。
- 解释 Agent 不接收必要范围外的私密材料；实验数据脱敏，真实内容不进公开仓库。

跨模型标准化只统一协议，不抹掉能力差异。能力矩阵与覆盖率见 [评测方案](BENCHMARK.md)。
